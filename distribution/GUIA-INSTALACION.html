01

Antes de empezar

Descarga el ZIP de esta entrega y extrae la carpeta completa. Conserva juntos README.md, AGENTS.md, los scripts y los archivos de dependencias. Abre esta guía con doble clic.

Para la primera prueba necesitas el paquete, Internet y un navegador. En Windows prepararás Ubuntu con WSL2. La app usa SQLite y no requiere contratar una base externa.
02

Elige tu equipo

Windows ejecuta ConectadOS dentro de Ubuntu. Esta entrega no incluye .exe. La instalación Linux está comprobada; el recorrido completo Windows/WSL2 se confirma con tu prueba.

APrepara Ubuntu

Si ya tienes WSL, revisa wsl --list --verbose en PowerShell y conserva tus distribuciones. Para una instalación nueva abre PowerShell como administrador:

PowerShell · solo preparación WSL
wsl --install -d Ubuntu-24.04

Reinicia si Windows lo solicita. Abre Ubuntu desde Inicio y crea su usuario Linux. Confirma que aparece VERSION 2 con wsl --list --verbose. Si falta esa distribución, consulta wsl --list --online y la guía oficial de Microsoft.

BCopia el proyecto al entorno Linux

Descomprime el ZIP en Windows. En la terminal de Ubuntu ejecuta explorer.exe .. Se abre tu carpeta Linux: copia allí la carpeta ConectadOS extraída, sin reemplazar otra instalación. Trabaja, por ejemplo, en ~/ConectadOS.

Guardar el proyecto en Linux evita el costo de acceso a archivos de Windows desde WSL. Recomendación de Microsoft.

CPide la instalación a tu agente Ruta recomendada

Si faltan, prepara Node 22 desde nodejs.org y verifica el archivo oficial antes de instalarlo, sin sustituir runtimes existentes. Ejecuta node scripts/install.mjs para revisar, node scripts/install.mjs --apply y npm start. Valida la demostración y el acceso. Conserva cualquier configuración existente. Prefiero instalar manualmente

En Windows, estos comandos van en Ubuntu después de preparar WSL; instala Node dentro de Ubuntu, no solo en Windows. En macOS o Linux usa su terminal. Entra primero en la carpeta del proyecto.

Terminal de macOS / Linux / Ubuntu WSL
node --version
npm --version
node scripts/install.mjs
node scripts/install.mjs --apply
npm start

El primer comando del instalador muestra un plan. --apply descarga las dependencias del lock, prepara, diagnostica y compila. Si aparece un error, conserva la carpeta y revisa el mensaje antes de continuar. No borres claves ni bases para corregirlo.

Abre la demostración: http://127.0.0.1:3119/preview. El mapa ficticio también está en /demo. Mantén abierta la terminal de npm start. En macOS/Linux el lanzador muestra la dirección loopback exacta; en WSL se accede desde el navegador de Windows mediante localhost.

Si 3119 está ocupado, una carpeta nueva admite node scripts/install.mjs --apply --port 4200. Usa entonces 127.0.0.1:4200. El instalador conserva el puerto de una instalación existente.

03

Crea tu cuenta

Abre /access. Usa el código del archivo local .keys/setup-token, elige un usuario y una contraseña de al menos 15 caracteres. Abre el archivo con un editor local y copia el código únicamente en la app; no lo envíes a un chat.

En Windows, el Explorador puede abrir la carpeta Linux desde explorer.exe .. Activa la vista de archivos ocultos si hace falta. El agente puede abrir el archivo para que tú lo uses, sin imprimir su contenido.

La cuenta empieza vacía. Los recursos de la demostración no se convierten en recursos tuyos. Google para iniciar sesión se configura después para el origen de esta instalación; es independiente del acceso a Drive.
Detener y volver a entrar

Ctrl+C detiene tu proceso. Para volver, abre Ubuntu o tu terminal, entra en la misma carpeta y ejecuta npm start. Cuenta y configuración se conservan. La versión local no instala un servicio de arranque automático en Windows; suspender el equipo o detener WSL interrumpe el panel.

04

Conecta un servicio cada vez

Después de probar la cuenta, abre Configuración. Cada proveedor explica el dato que pide, sus permisos y el enlace para obtenerlo. Usa accesos dedicados; guardar una clave no confirma que la conexión funcione.

Verifica que aparezcan tus recursos y una fecha reciente. Una lectura antigua, un permiso ausente o una ficha manual se muestran como tales. Las otras plataformas pueden registrarse manualmente sin activar una API.

IA, voz y costos

Mapa y resumen sin IA funcionan sin una API de modelos. Texto y voz comerciales requieren tu clave, proveedor, modelo y revisión de costos. La suscripción a un agente no incluye ese consumo. La voz toma las fuentes preparadas al inicio; no ejecuta cambios durante la llamada.

Para probar voz: dos preguntas, una interrupción y Finalizar. Comprueba que el micrófono se apague. Usa auriculares si aparece eco. El correo, almacenamiento y VPS también pueden cobrar según sus planes.

Copias en R2 y Drive

Son opcionales y se configuran por separado. Conserva las claves de recuperación fuera de la instalación y del almacenamiento. Primero crea una copia y recupérala en otro destino. R2 diario hace una primera copia al habilitarse y luego una diaria. Drive usa el instalador Linux guiado por agente, con permisos propios; entrar con Google no lo autoriza.

Estas copias protegen ConectadOS. Las bases que observas necesitan sus propios trabajos de respaldo; el panel muestra la evidencia que se haya enlazado. Consulta docs/INSTALL-DRIVE.md y docs/OPERATIONS.md dentro del paquete.

Instalar en un VPS / Coolify

Después de la prueba local, sigue deploy/README.md con tu agente. Usa un recurso nuevo, dominio propio con HTTPS y tres volúmenes privados independientes. El puerto interno 3000 queda detrás del proxy. Revisa capacidad antes de compilar. Esta guía local no crea DNS, repositorios ni infraestructura.
